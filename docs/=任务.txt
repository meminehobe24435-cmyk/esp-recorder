==================================================
一、项目技术要求
==================================================

目标芯片：

ESP32-S3

开发框架：

ESP-IDF 官方框架，使用 C 语言和 FreeRTOS。
禁止使用 Arduino 框架。

优先使用以下 ESP-IDF 官方功能：

- esp_wifi
- esp_event
- nvs_flash
- esp_http_server
- FATFS
- SDMMC 或 SDSPI
- UART Driver
- TinyUSB
- FreeRTOS Queue、EventGroup、Task Notification

代码必须采用组件化结构，不允许全部堆积在 app_main.c。

建议组件：

components/
├── app_config
├── wifi_manager
├── web_server
├── uart_bridge
├── data_router
├── recorder
├── storage_manager
├── usb_device
└── system_status

==================================================
二、本轮必须实现的网页
==================================================

创建一个完整、现代、适合手机和电脑访问的设备管理页面。

页面名称：

维特智能 WiFi 数据记录仪

页面至少包含：

1. 设备状态总览

显示：

- AP 状态
- Station 状态
- Station IP
- AP IP
- UART 状态
- 当前波特率
- SD 卡状态
- SD 卡容量
- 当前记录状态
- USB 工作模式
- 服务器连接状态
- 系统运行时间
- 剩余堆内存

2. 实时数据监控

必须区分：

- UART RX
- UART TX
- 系统日志

功能包括：

- 自动滚动
- 暂停显示
- 清空显示
- 十六进制/文本切换
- 时间戳显示开关
- 接收字节数统计
- 发送字节数统计

3. 数据发送区域

包括：

- 文本输入框
- 文本/HEX 模式
- 自动追加换行选项
- 发送按钮
- 发送历史

4. 记录控制

包括：

- 开始记录
- 停止记录
- 当前文件名
- 已记录字节数
- 已记录时长
- 记录状态提示

5. UART 参数配置

至少包含：

- 波特率
- 数据位
- 停止位
- 校验位
- 保存按钮

常用波特率：

9600、19200、38400、57600、115200、230400、460800、921600

6. WiFi 配网

包括：

- 当前 WiFi 状态
- SSID 输入
- 密码输入
- 显示密码
- 扫描 WiFi
- 信号强度
- 保存并连接
- 断开连接

密码不能写死在代码中，后续需要保存到 NVS。

7. SD 卡文件管理

显示：

- 文件名
- 文件大小
- 创建或修改时间
- 下载按钮
- 删除按钮
- 上传按钮
- 刷新文件列表

8. 页面视觉要求

- 响应式布局
- 手机浏览器可以正常操作
- 不使用必须联网加载的 CDN
- CSS、JavaScript 和图标均应能够离线工作
- 页面不能只是几行按钮
- 状态颜色清晰
- 操作按钮需要有反馈
- 危险操作需要二次确认
- 页面中文显示正常
- 页面中必须显示“维特智能”

==================================================
三、前后端接口
==================================================

前端不要只做一张静态效果图。

请设计并实现以下 REST API 或等价接口：

GET  /api/status
GET  /api/uart/config
POST /api/uart/config
POST /api/uart/send
POST /api/record/start
POST /api/record/stop
GET  /api/files
GET  /api/files/download
POST /api/files/upload
DELETE /api/files
GET  /api/wifi/status
GET  /api/wifi/scan
POST /api/wifi/connect
POST /api/wifi/disconnect

实时数据使用：

WebSocket /ws

WebSocket 消息至少支持：

- uart_rx
- uart_tx
- system_log
- status
- record_status

所有 API 必须：

- 校验参数
- 限制字符串长度
- 防止文件路径穿越
- 检查返回值
- 返回规范 JSON
- 对共享资源进行必要的同步保护

四、本地页面预览要求
==================================================

因为当前可能没有连接开发板，请同时建立本地页面预览机制。

要求：

1. ESP32 使用的网页源文件和本地预览使用同一套文件，不能维护两套完全不同的页面。

2. 创建类似目录：

web/
├── index.html
├── app.css
└── app.js

3. 页面必须具有两种数据模式：

- 真实设备模式：调用 ESP32 REST API 和 WebSocket
- 本地预览模式：API 不可用时使用明确标记的模拟数据

4. 模拟模式必须在页面上明显显示：

“本地预览模式，当前数据为模拟数据”

5. 模拟数据需要动态变化，让我能看到：

- UART 数据不断进入
- 运行时间增加
- RX/TX 字节数变化
- 记录状态变化
- 文件列表操作反馈
- WiFi 状态变化

6. 不允许把模拟实现混入底层 ESP32 驱动逻辑。

==================================================
五、ESP-IDF 集成要求
==================================================

将网页资源嵌入 ESP-IDF 固件。

可以根据当前 ESP-IDF 版本选择：

- EMBED_FILES
- EMBED_TXTFILES
- 生成 C 数组

优先使用 ESP-IDF 官方推荐方式。

必须检查：

- Content-Type
- UTF-8
- 缓存策略
- HTML、CSS、JS 路由
- 404 处理
- API 路由优先级
- WebSocket 路由

实现最小可运行的 WiFi AP 模式：

SSID 暂时使用：

WIT-LOGGER-XXXX

其中 XXXX 来源于设备 MAC 地址后四位，不要固定写死。

默认 AP 地址优先使用：

192.168.4.1

页面入口：

http://192.168.4.1/

暂时没有确认产品密码时，密码放到集中配置位置，并明确标注生产版本必须修改。

实际启动网页预览。

python -m http.server 8080 --directory web

如果 python 命令不可用，则尝试：

需要使用不会阻塞后续任务的后台或独立进程方式启动。

实际检查页面：

- HTTP 返回成功

- JavaScript 可以访问

http://127.0.0.1:8080/
http://127.0.0.1:8080/app.css
http://127.0.0.1:8080/app.js

步骤 10：

尝试使用 Windows PowerShell 打开浏览器：

powershell.exe -NoProfile -Command "Start-Process 'http://127.0.0.1:8080/'"

必须实际调用，不要只告诉我怎么调用。

步骤 11：

生成页面截图。

先自动检测 Edge 或 Chrome 路径。

优先尝试 Edge：

"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"

或：

"C:\Program Files\Microsoft\Edge\Application\msedge.exe"

截图命令参考：

msedge.exe --headless --disable-gpu --window-size=1440,1000 --screenshot=artifacts/dashboard.png http://127.0.0.1:8080/

如果 Edge 不存在则检测 Chrome。

截图必须保存到：

artifacts/dashboard.png

截图完成后：

- 检查文件确实存在
- 读取并检查截图
- 确认页面没有严重错位、空白或中文乱码
- 如有问题，修改页面并重新截图

步骤 12：

如果系统能够明确识别到唯一的 Espressif 开发板串口，可以给出烧录建议，但不要在无法确认串口身份时向错误设备烧录。

无法确认串口时，不要编造硬件测试结果。
